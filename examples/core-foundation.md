# Shared foundation usage

These snippets are intended to compile against the public `cca-core` headers.
They demonstrate engineering-foundation behavior only.

## Immutable configuration snapshot

```cpp
#include <cca/core/configuration.hpp>

#include <string>
#include <utility>

cca::core::ConfigurationBuilder builder;
builder.set(cca::core::ConfigurationKey{"output_directory"}, "build/output");
builder.set(cca::core::ConfigurationKey{"mode"}, "foundation");

const cca::core::Configuration configuration = std::move(builder).build();
const std::string mode =
    configuration.get_or(cca::core::ConfigurationKey{"mode"}, "default");
```

`ConfigurationKey` is the strong key type, `ConfigurationBuilder` owns
mutation during construction, and `Configuration` is the immutable snapshot.
The snapshot does not read files, environment variables, or CLI arguments.

## Filtered logger and stream sink

```cpp
#include <cca/core/logging.hpp>

#include <memory>
#include <sstream>

std::ostringstream output;
auto sink = std::make_shared<cca::core::OstreamLogSink>(output);
cca::core::Logger logger{sink, cca::core::LogLevel::warning};

logger.info("example", "filtered by the minimum level");
logger.warning("example", "recorded in the caller-owned stream");
```

The stream must outlive `OstreamLogSink`. The shared sink lifetime permits more
than one `Logger` to use the same synchronized sink. `LogEntry` is the value
passed to a sink, and `to_string(LogLevel)` supplies the stable lowercase level
name.

## Deliberately quiet logger

```cpp
#include <cca/core/logging.hpp>

#include <memory>

auto sink = std::make_shared<cca::core::NullLogSink>();
cca::core::Logger logger{sink};
logger.info("example", "intentionally discarded");
```

`NullLogSink` is preferable to a nullable dependency or global switch when a
consumer deliberately wants no log output.

## Recording sink for tests

```cpp
#include <cca/core/logging.hpp>
#include <cca/testing/recording_log_sink.hpp>

#include <memory>

auto sink = std::make_shared<cca::testing::RecordingLogSink>();
cca::core::Logger logger{sink, cca::core::LogLevel::debug};
logger.debug("example", "captured");

const auto entries = sink->snapshot();
sink->clear();
```

`RecordingLogSink` owns copies of entries and provides thread-safe
`snapshot()` and `clear()` operations. It is test support, not a production
persistence or telemetry system.

## ASCII string utilities

```cpp
#include <cca/core/string_utils.hpp>

const auto trimmed = cca::core::strings::trim_ascii("  CCA  ");
const auto normalized = cca::core::strings::to_lower_ascii(trimmed);
const bool blank = cca::core::strings::is_blank_ascii(" \t\r\n");
```

The functions intentionally use ASCII rules so their results do not depend on
the process locale. They do not provide Unicode normalization.

## Shared semantic version

```cpp
#include <cca/core/version.hpp>

#include <string>

const cca::core::SemanticVersion version = cca::core::current_version();
const std::string printable_version = version.to_string();
```

`SemanticVersion` is a value type with explicit major, minor, patch,
prerelease, and build-metadata fields. `current_version()` returns the version
generated by the workspace build configuration. It does not define the
unresolved cross-repository compatibility or release policy.
