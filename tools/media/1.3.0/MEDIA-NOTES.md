## Export settings used (re-check platform limits before posting)

- **Ad files (4):** H.264 High profile, level 4.2, `yuv420p`, 30 fps constant, CRF 16 / preset slow; AAC-LC 128 kbps stereo 44.1 kHz; `-movflags +faststart` (verified: `moov` precedes `mdat`). Largest is 8.7 MB (limit set by brief: 100 MB).
- **Demo MP4:** H.264 High, `yuv420p`, 30 fps, CRF 18 / preset slow, +faststart; a silent AAC stereo track (no narration).
- **GIF:** ffmpeg two-pass palette (`palettegen max_colors=128 stats_mode=diff`, `paletteuse` Bayer dither), 12 fps, 1280 px wide, infinite loop, under the 15 MB cap.
- **Audio of the ads:** self-generated by `tools/media/make-audio.mjs` (synthesised pad, low hits on cuts, short ticks, a riser; no samples, no third-party music). The ads also work with sound off: all message text is burned in, and text is laid out inside the central 80 % of the frame (about 10 % margin each side).
- Platform limits (maximum length, size, aspect ratios, caption and audio rules for LinkedIn and X) were **not** re-verified against the platforms in this session. Re-check them before posting.

## How it was made (all reproducible; scripts in `tools/media/`)

Environment: Windows 11 (10.0.26200), Node v24.14.0, Microsoft Edge 155.0.4283.45 (headless, DevTools protocol, Node built-ins only: global `fetch`/`WebSocket`, `child_process`), FFmpeg 9.0.2 (`Gyan.FFmpeg` via `winget install --id Gyan.FFmpeg -e`, full build from gyan.dev), Git 2.55.0, GitHub CLI 2.102.0. MemoryOS CLI/SDK 1.2.0 as shipped in v1.3.0.

1. `prepare-records.mjs` writes the released test-fixture records (the MO-1308 test corpus builder, real SDK, released fixtures) and the three MO-1306 policy vectors as plain files into the scratch workspace `C:\mos-media\work\demo` (outside the repository).
2. `run-session.mjs` + `session-plan*.mjs` run **every** on-screen command for real and record stdout, stderr and exit code (`transcript*.json`). The plans: walkthrough (`session-plan.mjs`), GIF (`session-plan-gif.mjs`), ad (`session-plan-ad.mjs`).
3. `render-walkthrough.mjs` (+ `scene/walkthrough.html`, `scene/chrome.js`, `walkthrough-script.mjs`, `gif-script.mjs`) renders terminal pages from the transcript and drives the real generated `dashboard.html` in Edge (scrolling, changing the real select controls, expanding a row); each unique frame is an Edge screenshot, assembled by FFmpeg.
4. `capture-stills.mjs` takes 2x stills of the real dashboard for the ad; `render-ad.mjs` + `scene/ad.html` render each ad frame per aspect ratio (re-composed layouts: side-by-side for 16:9, stacked for 1:1 and 4:5, with ratio-specific type sizes and crops), `make-audio.mjs` makes the sound bed.

Commands (from the worktree root):


Commands in the CLI sessions run as `node repositories/memoryos-cli/bin/memoryos.js ...`; they are displayed as `memoryos ...` (the readable form the quick-start guide itself uses).

## Limitations and honest disclosures

- **Records are released test fixtures.** The ledger entries (MIP package, checkpoints, Policy evaluations, regression report, CI/CD run, readiness results, decision claims) come from the repository's released fixtures, not from a real release process. The walkthrough says so on its MO-1308 title card. The readiness results shown are fixture results, not the readiness of MemoryOS 1.3.0 itself.
- **Terminal sessions are rendered, not recorded.** Each terminal frame is an HTML page filled with the real captured text; typing speed, line reveal and the cursor are animation. Long outputs are shown in full in the walkthrough and GIF. The **ad shows excerpts** (whole, unmodified lines such as `index: 0`, `entryCount: 4`) and abbreviates two displayed script paths (`node tamper-copy.mjs`, `node memoryos-dashboard-generator.mjs`; the real commands used `tools/media/...` and `repositories/cca-studio/scripts/...`).
- **MO-1302 to MO-1307 are shown as shipped files, not as live runs.** The MCP server and the CI runner refuse to start on this host's Node (they require the pinned Node 24.21.0 and a trusted launcher; this host has v24.14.0), the REST gateway needs TLS material and a launcher, and the VS Code extension needs VS Code. The walkthrough shows real file contents read with `ls`/`grep` (workflow template settings, VS Code command titles, MCP tool names, REST routes, readiness results) and labels them "Shipped file contents" / "Recorded readiness results (released fixtures)". Captions repeat the release qualifications (GitHub CI: implemented and offline-validated, hosted certification not claimed; VS Code: macOS not executed; MCP: macOS unsupported; REST: Windows 11 x64 host only). The CI scene's result bundle (`COULD_NOT_EVALUATE`) is a released fixture.
- **Dashboard capture:** Edge runs headless (same renderer) and the page is the real generated file. The caption bars and the amber highlight ring are overlays injected by the harness; to let the overlay styles apply, the harness turns on the DevTools "bypass CSP" switch for that capture only (the dashboard's own code is untouched). The page is shown at 1.5x zoom so it is legible at 1080p. Select controls are changed by script (`change` events), not by a mouse. The Edge look in the ad ("Microsoft Edge · local file") is a plain label on a window frame I drew, not a screenshot of Edge's own chrome.
- **Dark theme** of the dashboard is Edge's default `prefers-color-scheme` in this headless profile; the page ships light and dark styles.
- No narration (the MP4 and GIF are silent; the ads carry a generated sound bed). No third-party logos, music, stock footage or people. "Microsoft Edge" and "GitHub" appear as plain text only.
- Wording follows the release disclosures: no hosted service, accounts or multi-user claim; "cloud" is never used without "static"; `decisionConsistency` is described as informational and the dashboard's own label ("Recorded as differing from its readiness result") is used; readiness is never presented as approval; the 10,000-entry certified scale is the only scale mentioned; no superlatives. The repository is public but grants no software license, so nothing says "open source".
- `tools/verify_workspace.py`, tests and the repository itself were not run or modified; only `tools/media/` was added in the worktree.
- The Windows Smart App Control caveat from KNOWN_ISSUES.md did not affect the work (only the Node-based CLI and generator were used).
- If the media is regenerated, ledger identifiers and digests are reproducible (the same records give the same bytes).
