# Developer setup

This guide prepares a local checkout for foundation development. It does not
establish the project's unresolved long-term compiler support matrix.

## Prerequisites

| Tool | Requirement | Purpose |
|---|---|---|
| CMake | 3.28 or newer for the workspace root | Configure and generate builds |
| C++ compiler | C++23-capable | Build foundation libraries, Standards Compiler, CLI, and tests |
| Ninja | Available on `PATH` for workspace presets and bootstrap | Build targets generated by the preset-selected Ninja generator |
| vcpkg | Bootstrapped by the workspace or an existing compatible checkout | Resolve the manifest dependency on GoogleTest |
| Git | Current supported release | Work with the source checkout and vcpkg |
| Python | 3.12 or newer when running Python engineering tools | Secondary tooling only |

Optional quality tools:

- `clang-format` for formatting checks and fixes;
- `clang-tidy` for compiler-integrated static analysis;
- `cppcheck` for additional static analysis;
- `gcovr` plus GCC or Clang coverage support for coverage reports;
- platform sanitizer support for the selected compiler.

Install the pinned Python CI helper dependency in an isolated environment when
coverage reporting is needed:

```sh
python -m pip install -r tools/requirements-ci.txt
```

This installs `gcovr`; clang-format, clang-tidy, cppcheck, and compiler
sanitizers come from the selected platform toolchain.

The exact compiler, vcpkg baseline, quality-tool versions, and support window
are unresolved in CCA-A009 and CCA-A012. Use the versions selected by continuous
integration when that matrix is available, and report the actual versions with
any defect.

## Obtain the workspace

Start from an authorized source checkout and change to the directory containing
the top-level `CMakeLists.txt`. No canonical clone URL or repository topology is
specified, so this guide does not invent one.

Expected implementation directories for this milestone are:

```text
repositories/cca-core
repositories/cca-compiler
```

Other repository directories are reserved. Their absence or emptiness must not
be "fixed" by implementing future systems.

## Recommended bootstrap

The bootstrap scripts acquire the workspace-pinned vcpkg checkout under the
ignored `.cache/vcpkg` directory, bootstrap vcpkg, and configure the selected
preset. The current pin is vcpkg tag `2026.06.24` at commit
`cd61e1e26a038e82d6550a3ebbe0fbbfe7da78e3`; the manifest uses the same commit
as its builtin baseline.

PowerShell:

```powershell
pwsh -File scripts/bootstrap.ps1
```

POSIX shell:

```sh
bash scripts/bootstrap.sh
```

Choose a configure preset:

```powershell
pwsh -File scripts/bootstrap.ps1 -Preset analysis
```

```sh
bash scripts/bootstrap.sh --preset analysis
```

Use `-SkipVcpkg` / `--skip-vcpkg` only when the required pinned checkout is
already present at `.cache/vcpkg` or when configuration is also skipped. Use
`-SkipConfigure` / `--skip-configure` to prepare dependencies without
generating a build.

Bootstrap performs network and filesystem work in `.cache`; it does not prove
that targets build or tests pass. Review scripts before running them in a
controlled or offline environment.

## Use an existing vcpkg checkout

Manual configuration may use an existing compatible vcpkg checkout. Expose its
root to the shell without committing a machine-specific path:

PowerShell:

```powershell
$env:VCPKG_ROOT = 'C:\path\to\vcpkg'
```

POSIX shell:

```sh
export VCPKG_ROOT=/path/to/vcpkg
```

The CMake toolchain path is
`${VCPKG_ROOT}/scripts/buildsystems/vcpkg.cmake`.

Do not place a personal vcpkg checkout or installed dependency tree inside
source control. Dependency acquisition needs network access unless packages
are already cached. Review the unresolved supply-chain and license policy in
CCA-A009 before changing dependencies.

## First configure

The standard workspace entry point after bootstrap is the `default` CMake
preset:

```sh
cmake --preset default
```

If the active preset cannot locate vcpkg, supply the toolchain in a separate
local build directory:

```sh
cmake -S . -B out/local \
  -DCMAKE_TOOLCHAIN_FILE="${VCPKG_ROOT}/scripts/buildsystems/vcpkg.cmake" \
  -DBUILD_TESTING=ON
```

On PowerShell, the same manual configure is:

```powershell
cmake -S . -B out/local `
  "-DCMAKE_TOOLCHAIN_FILE=$env:VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake" `
  -DBUILD_TESTING=ON
```

See [build-instructions.md](build-instructions.md) before enabling analysis,
sanitizers, warnings-as-errors, or coverage. Use a separate build directory for
materially different instrumentation.

For a dependency-free structural configure/build that intentionally disables
tests, use the `minimal` preset. That preset is useful for inspecting the
foundation without vcpkg; it has no test preset and is not a replacement for
the test-enabled workflow.

## Verify the local toolchain

Record versions before diagnosing a build:

```sh
cmake --version
ctest --version
```

Also record the compiler, generator, vcpkg revision/baseline, host operating
system, and preset or full configure command. A successful configure indicates
only that CMake generated the selected build; it is not proof that all targets
build or tests pass.

## IDE integration

The workspace exports `compile_commands.json` for generators that support it.
Preset builds place it under `out/build/<preset>`. Point the IDE's C++ tooling
to the selected build directory. Do not commit editor-specific absolute paths,
local build directories, or user presets that contain secrets.

IDE integration is a convenience layer. The documented command-line configure,
build, and test workflow remains the reproducible diagnostic baseline.

## Common setup failures

### CMake cannot find GoogleTest

Confirm that vcpkg manifest/toolchain integration is active and that the
selected dependency set has been installed. Do not silently disable tests to
make configuration appear successful.

### The compiler rejects C++23

Select a newer compiler or a matching toolchain. Do not lower
`CMAKE_CXX_STANDARD` or enable non-standard extensions.

### clang-tidy, cppcheck, or gcovr is missing

Install the requested optional tool or configure without that optional mode.
Do not describe the check as having run when it was skipped.

### A sanitizer combination is rejected

ThreadSanitizer and AddressSanitizer cannot be enabled together in the current
foundation. MSVC support is limited to AddressSanitizer among the configured
sanitizers. Use a compiler/platform-supported combination in its own build
directory.

### A reserved repository is skipped

The top-level workspace may skip a repository that has no `CMakeLists.txt`.
For reserved future repositories this is expected and is not a missing feature
in the IS-002 compiler milestone.
