# MemoryOS 1.3.0

MemoryOS 1.3.0 is released as tag `v1.3.0` (commit `889f99e7`). It comprises nine milestones, MO-1301 to MO-1309, each at its own annotated tag. The release commit is documentation only on top of the recorded milestone and maintenance commits: it adds no code, test or evidence.

CCA-MEMORYOS-1.0 remains the published Standard ([MemoryOS Standard repository](https://github.com/moelsaka01/memoryos-specification)). Limits and qualifications are listed in [KNOWN_ISSUES.md](https://github.com/moelsaka01/memoryos-specification/blob/v1.3.0/KNOWN_ISSUES.md); please read it before relying on a milestone's certification. Full detail: [RELEASE_NOTES.md](https://github.com/moelsaka01/memoryos-specification/blob/v1.3.0/RELEASE_NOTES.md).

## Highlights

- **MO-1301 Investigation Policies:** deterministic engineering-policy subsystem over the corrected v1.2.1 baseline, with closed Policy and Policy Set artifacts, six registered rules, deterministic PASS/FAIL/COULD_NOT_EVALUATE aggregation, and SDK/CLI 1.1 integration.
- **MO-1302 GitHub Actions and Deterministic CI Policy Gates:** GitHub-specific CI integration over the MO-1301 Policy authority.
- **MO-1303 VS Code Extension:** released under an explicit external-infrastructure exception: Ubuntu and Windows hosted certification PASS; macOS hosted certification and three-platform parity NOT EXECUTED because of an external GitHub runner-allocation and billing restriction.
- **MO-1304 MCP Server and Agent Integration:** certified for Windows 11 x64 and Ubuntu 24.04 LTS x64 with two-platform parity PASS; macOS remains unsupported for MO-1304.
- **MO-1305 REST Gateway:** six SDK-backed semantic operations and three operational endpoints under `/v1`, native TLS over HTTP/1.1, bearer authentication and a dependency-free Node adapter. Installed-package certification ran on the existing physical Windows 11 x64 host only.
- **MO-1306 Provider-Neutral CI/CD Integration:** one SDK-backed provider-neutral core with a native Windows generic runner and deterministic GitLab, Jenkins, Azure and GitHub provider files. The generic runner is REAL_EXECUTION_CERTIFIED; the GitHub integration is IMPLEMENTED, OFFLINE_VALIDATED and NOT_CERTIFIED hosted. Released with qualified certification.
- **MO-1307 Release Governance and Readiness:** deterministic, evidence-backed readiness assessment of an exact candidate; final release authorization remains human. The read-only validator reported `CERTIFIED_READY_TO_TAG`; 632 of 639 conformance tests passed at the tag with 7 disclosed stale-baseline tests, fixed afterwards by a test-only correction (639/639 on the reference Windows host under Node v24.21.0).
- **MO-1308 Investigation History:** a local, file-based, append-only, hash-chained ledger with deterministic query and the `MemoryOSHistoryExport` bundle, through the JavaScript SDK and the `memoryos history` CLI namespace. Certifying generations `phase3a` 108/108, `phase3b` 26/26, `phase3c` 67/67, and `phase3d` accepted by the read-only validator. The claim is local single-user v1 on native Windows 11 x64.
- **MO-1309 Cloud Dashboard:** a static, offline, strictly read-only dashboard over a verified MO-1308 history export, generated as one self-contained HTML file. MemoryOS ships no hosting, server, accounts, tenancy, billing or network access. Validated `CERTIFIED_READY_TO_TAG`; the certified scale is 10,000 entries.
- **Pre-release maintenance (PR #4):** an owner-approved POSIX fix making the Core transport pipes close-on-exec in `core_process.cpp`, plus test, tooling and CI fixes with no product semantics changed. Coverage meets the 90 % line gate.

## Compatibility

- **SDK and CLI 1.2.0.** MO-1308 moves the JavaScript SDK and the CLI from 1.1.0 to 1.2.0, additively and outside the CCA-MEMORYOS-1.0 baseline claim.
- **Released bundles are unchanged.** Released packages, vendored closures and tags are byte-identical; vendored copies inside a released package are not refreshed.
- **Standard.** CCA-MEMORYOS-1.0 remains the published Standard. MO-1309 creates no Standard requirement and needs no CCA-MEMORYOS-1.1.
- **Baseline.** MemoryOS 1.3 is additive over the corrected v1.2.1 baseline.

## Known issues

The complete list is in [KNOWN_ISSUES.md](https://github.com/moelsaka01/memoryos-specification/blob/v1.3.0/KNOWN_ISSUES.md). In summary:

- **MO-1308 claim scope:** local single-user v1 on native Windows 11 x64 only. The ledger is integrity-checked, not authenticated, encrypted or signed. Truncation or rollback is detectable only through an externally recorded `headDigest`; a directory swap is detected after the fact, never prevented (H40, A6, Q01 to Q15).
- **MO-1309:** an integrity view as of generation, not evidence of authenticity, completeness, currency or approval. The certified scale is 10,000 entries; 100,000 entries are characterized only, with no support claim.
- **Windows access violation (open, deferred to post-1.3.0):** `MemoryProviderAllocationFailureTest.DescriptorWorkspaceFailureConstructionPreservesCompleteState` dies with `0xC0000005` on windows-2022. It is not fixed and not excluded, and a product defect is not ruled out. Hosted Windows CI therefore shows this test failing.
- **macOS:** a microsecond `pipe()`/`fcntl()` window remains in the Core transport pipe creation (accepted by owner decision); macOS is unsupported for MO-1304, and MO-1303 macOS certification was NOT EXECUTED.
- **Smart App Control** is enforcing on the Windows 11 reference host and blocks a build-dependent set of freshly built unsigned executables; native C++ verification belongs on a host without it.
- **Open follow-ups:** the shared test failures recorded by MO-1309, `tools/verify_workspace.py` exiting 2 in a fresh worktree, and Windows CI green with native C++ tests on a host without Smart App Control.
- **Carried from v1.2.1:** Observe to Trace discoverability (low impact); source license pending an owner decision, the repository grants no software license.
