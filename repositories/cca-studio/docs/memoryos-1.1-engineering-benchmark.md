# MemoryOS 1.1 Engineering Benchmark

## Purpose

This is the reproducible benchmark contract for MO-1108. It separates semantic-engine work from browser rendering so that each measurement has one clear meaning.

## Artifacts

- `benchmarks/memoryos-scalability-fixture.mjs` builds exact, deterministic 100–10,000-node accepted observations.
- `benchmarks/memoryos-scalability.mjs` measures startup, observation acceptance, Trace, Replay, Evolution, Comparative Reconstruction, renderer preparation, retained heap, and worst-case trace alignment.
- `benchmarks/memoryos-1.1-benchmark-results.json` is the recorded five-sample result from the environment in the performance report.
- `benchmarks/memoryos-1.1-browser-render-results.json` is the recorded release-browser rendering result.
- `web/benchmark.html` and `web/js/browser-render-benchmark.js` measure actual browser DOM and frame behavior.
- `tests/memory_studio_scalability_test.mjs` is the deterministic scalability regression suite.

## Measurement definitions

| Measurement | Boundary |
| --- | --- |
| Startup | Process start through benchmark entry after production module loading |
| Accepted observation | Detached snapshot, graph projection, immutable world, and observation-frame acceptance |
| Trace generation | Exact Reflection query through canonical immutable Cognitive Trace validation |
| Replay | Replay construction, every deterministic transition, and every projection |
| Evolution | Two accepted frames through immutable semantic difference result |
| Comparative reconstruction | Two validated traces through aligned immutable reconstruction |
| Comparative replay | Every synchronized step, explicit divergence resumes, and final projection |
| Renderer preparation | Trace, Evolution, and Comparative renderer-consumption validation/preparation |
| Retained heap | Complete live two-frame investigation after explicit garbage collection |
| DOM construction | Browser invocation through complete `renderGraph` return |
| Frame delivery | Browser invocation through the next `requestAnimationFrame` callback |
| Visual settle | Actual post-cold-frame task boundary, measured before interaction |
| Interaction | Real steady-state semantic-node click through synchronous delta emphasis and next browser frame |

Setup work is performed outside each timed operation. Five independent samples are sorted; the report records minimum, median, p95, and maximum. No result is discarded.

## Commands

```console
cd repositories/cca-studio

# Repeat the release measurement.
node --expose-gc benchmarks/memoryos-scalability.mjs \
  --samples=5 \
  --output=benchmarks/memoryos-1.1-benchmark-results.json

# Run only selected sizes while investigating a regression.
node --expose-gc benchmarks/memoryos-scalability.mjs \
  --sizes=1000,10000 \
  --samples=3

# Run deterministic scalability gates.
npm run test:scalability

# Serve and run the native browser benchmark.
npm start
# Open http://127.0.0.1:4173/benchmark.html?autorun=1
```

PowerShell users should place the Node command on one line or use PowerShell continuation syntax instead of the POSIX backslashes shown above.

## Interpretation rules

- Compare results only on equivalent hardware, runtime, sample count, and browser viewport.
- Treat p95 as the release-review latency; use the median for trend comparison.
- Do not infer browser paint performance from Node renderer preparation.
- Do not infer semantic-engine performance from DOM cardinality.
- A highlighted difference or replay step is never generated by benchmark code; benchmarks invoke the same deterministic production modules.
- Tight timing assertions are intentionally excluded from unit tests because shared CI scheduling is nondeterministic. Tests assert semantic results, cardinality, canonical ordering, storage strategy, and scale completion.

## Architecture boundary

Benchmark modules are development tooling. Production engines do not import them. The renderer imports neither benchmark fixture nor benchmark results. The browser benchmark creates deterministic graph data locally and never changes runtime state.
